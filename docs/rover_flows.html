Fluxos do Chat Rover

Guia técnico interativo com as jornadas de busca de agências, edição de perfil por voz e candidatura com lembretes automatizados no Estagionauta.

1. Listar Agências em Recife (Apenas Nomes)

Quando o usuário solicita a listagem de agências aprovadas em Recife, o Rover utiliza a ferramenta de busca de banco de dados e retorna estritamente a informação requisitada formatada pelo LLM.

sequenceDiagram
    autonumber
    actor U as Usuário
    participant FE as Frontend (RoverDrawer.tsx)
    participant BE as Backend (rover.routes.ts)
    participant LLM as Gemini 1.5 Flash
    participant DB as Supabase (agencies)

    U->>FE: Digita "me mostre 5 agências em Recife, apenas os nomes"
    FE->>BE: POST /api/rover/message { message: "..." }
    BE->>DB: Insere mensagem do usuário em "rover_messages"
    BE->>LLM: Envia Prompt do Sistema + Histórico de Mensagens
    Note over LLM: Identifica a intenção de buscar agências
    LLM-->>BE: Solicita chamada da ferramenta "search_agencies" com args { city: "Recife" }
    BE->>BE: Chama executeRoverTool('search_agencies', { city: 'Recife' })
    BE->>DB: SELECT em "agencies" WHERE city ILIKE '%Recife%' AND status = 'approved'
    DB-->>BE: Retorna lista de agências de Recife
    BE->>DB: Salva resposta da ferramenta em "rover_messages"
    BE->>LLM: Re-envia histórico contendo o resultado da ferramenta
    Note over LLM: Formata a resposta final contendo apenas os nomes conforme instrução do usuário
    LLM-->>BE: Retorna texto da resposta final
    BE->>DB: Salva resposta do assistente em "rover_messages"
    BE-->>FE: HTTP 200 { response: "Aqui estão as agências..." }
    FE->>U: Renderiza os nomes das agências na tela

📂 Componentes e Ficheiros Envolvidos

🖥️ Frontend

  • src/components/rover/RoverDrawer.tsx Gerencia o Drawer e dispara o envio do texto para a rota de mensagens.

⚙️ Backend

  • api/src/routes/rover.routes.ts Processa a chamada da API, moderando, redigindo PII e orquestrando o loop do LLM.
  • api/src/tools/search_agencies.ts Define search_agencies e a função runSearchAgencies que consulta o banco.

🗄️ Banco de Dados

  • Tabela: agencies Filtra por city ILIKE '%Recife%' e status da agência homologada (approved).

🧠 IA / Modelo

  • Modelo: gemini-1.5-flash Executa a chamada principal, mapeia os parâmetros da ferramenta e sintetiza a saída textual contendo apenas os nomes.

2. Alterar Informação do Perfil via Áudio

O usuário aciona o microfone no chat Rover, dita a alteração e o assistente executa o update em banco de dados, sinalizando à UI para invalidar o cache de dados e atualizar a visualização em tempo real.

🔍 Ampliar
sequenceDiagram
    autonumber
    actor U as Usuário
    participant FE as Frontend (RoverDrawer.tsx)
    participant browser as Web Speech API (Browser)
    participant BE as Backend (rover.routes.ts)
    participant LLM as Gemini 1.5 Flash
    participant DB as Supabase (user_profiles)

    U->>FE: Clica no botão "Falar"
    FE->>browser: Inicializa SpeechRecognition (lang: pt-BR)
    U->>FE: Fala: "mude meu linkedin para..."
    browser-->>FE: Retorna texto transcrito em tempo real
    U->>FE: Clica em "STOP" ou para de falar
    FE->>BE: POST /api/rover/message { message: "mude meu linkedin para..." }
    BE->>LLM: Envia histórico + mensagem transcrita
    Note over LLM: Reconhece a intenção de editar dados cadastrais
    LLM-->>BE: Solicita ferramenta "update_profile" com args { linkedin_url: "..." }
    BE->>BE: Chama executeRoverTool('update_profile', { linkedin_url: '...' })
    BE->>DB: UPDATE "user_profiles" SET linkedin_url = '...' WHERE id = userId
    DB-->>BE: Confirmação de update
    BE->>LLM: Envia resultado da ferramenta { success: true }
    LLM-->>BE: Retorna texto de confirmação final: "Prontinho! Atualizei seu LinkedIn..."
    BE-->>FE: HTTP 200 { response: "...", invalidates: ["profile"] }
    Note over FE: Identifica "invalidates: ['profile']"
    FE->>FE: queryClient.invalidateQueries(['profile'])
    Note over FE: Atualiza dados de perfil na tela em tempo real sem F5!
    FE->>U: Exibe mensagem de sucesso e atualiza a UI

📂 Componentes e Ficheiros Envolvidos

🖥️ Frontend

  • src/components/rover/RoverDrawer.tsx Usa SpeechRecognition (ou webkitSpeechRecognition) para transcrever a voz em texto localmente no navegador do usuário.

⚙️ Backend

  • api/src/tools/update_profile.ts Define os parâmetros aceitos do perfil e executa runUpdateProfile salvando o novo valor de LinkedIn.
  • api/src/tools/registry.ts Mapeia 'update_profile': ['profile'] em toolInvalidations.

🗄️ Banco de Dados

  • Tabela: user_profiles Atualiza a coluna linkedin_url associada ao ID do usuário autenticado.

🔄 Sincronização

  • React Query (Query Keys) O frontend recebe invalidates: ['profile'] e invalida o cache, recarregando automaticamente os componentes da página de Perfil.

3. Cadastro de Candidatura por Documento & Sugestão de Lembretes

Ao submeter o documento da vaga, o Rover lê os dados por IA, realiza o cadastro no Kanban de processos seletivos e automaticamente sugere ou cria lembretes de prazos no calendário do usuário.

🔍 Ampliar
sequenceDiagram
    autonumber
    actor U as Usuário
    participant FE as Frontend (RoverDrawer.tsx)
    participant BE as Backend (rover.routes.ts)
    participant LLM as Gemini 1.5 Flash
    participant DB as Supabase (kanban & reminders)

    U->>FE: Anexa documento (ex: "vaga_google.pdf") e digita "me cadastra nessa vaga"
    Note over FE: O texto de envio fica: "[Arquivo: vaga_google.pdf] me cadastra nessa vaga"
    FE->>BE: POST /api/rover/message { message: "..." }
    BE->>LLM: Envia Prompt do Sistema + Texto do Documento
    Note over LLM: Lê os detalhes da vaga (Google, Software Engineer, enviar teste até dia 25/06)
    LLM-->>BE: Solicita ferramenta "add_candidatura" com args { company: "Google", position: "Software Engineer", ... }
    BE->>BE: Executa runAddCandidatura
    BE->>DB: INSERT INTO "kanban_applications"
    DB-->>BE: Retorna ID da candidatura inserida (Ex: "candidatura_uuid_123")
    BE->>LLM: Retorna o ID criado
    Note over LLM: Percebe que há um teste técnico agendado para dia 25/06 no documento
    LLM-->>BE: Solicita ferramenta "create_reminder" com args { title: "Enviar teste Google", reminderAt: "2026-06-25T14:00:00Z", candidatureId: "candidatura_uuid_123" }
    BE->>BE: Executa runCreateReminder
    BE->>DB: INSERT INTO "user_reminders" (title, reminder_at, candidature_id, status: 'pending')
    DB-->>BE: Confirmação de gravação do lembrete
    BE->>LLM: Retorna sucesso do lembrete
    LLM-->>BE: Retorna texto consolidado: "Vaga cadastrada e lembrete agendado!"
    BE-->>FE: HTTP 200 { response: "...", invalidates: ["candidatures"] }
    FE->>FE: queryClient.invalidateQueries(['candidatures'])
    FE->>U: Exibe a resposta final e atualiza visualmente o Kanban do usuário

📂 Componentes e Ficheiros Envolvidos

🖥️ Frontend

  • src/components/rover/RoverDrawer.tsx Botão de anexo (Paperclip) que insere a tag de identificação do arquivo no corpo da mensagem.

⚙️ Backend & Ferramentas

  • api/src/tools/add_candidatura.ts Registra a vaga no Kanban do usuário com campos como company, position e status.
  • api/src/tools/create_reminder.ts Cria agendamento de notificação ligada à candidatura, prevenindo prazos perdidos.

🗄️ Banco de Dados

  • Tabela: kanban_applications Armazena os detalhes estruturados extraídos pela IA do arquivo.
  • Tabela: user_reminders Salva o prazo (data limite e título do lembrete).

🧠 Inteligência Artificial

  • Modelo: gemini-1.5-flash Interpreta o documento enviado, identifica a data futura de teste técnico e decide autonomamente chamar sequencialmente as ferramentas de criação de vaga e criação de lembrete.
